# 모듈 5. 서비스 상태와 로그 확인

## 1. 실습 목적

Linux 서버에서 서비스가 정상적으로 동작하는지 확인하고, 서비스의 로그와
네트워크 포트 상태를 함께 확인한다.

이번 실습에서는 `systemctl`, `journalctl`, `ss`를 사용하여 SSH 서비스를
기준으로 상태 확인 → 로그 확인 → 포트 확인 과정을 실습했다.

또한 서비스 장애가 발생했을 때 명령어를 이용해 원인을 좁혀가는 기본적인
장애 분석 흐름을 이해하는 것을 목표로 한다.

------------------------------------------------------------------------

## 2. 실습 환경

-   OS: Ubuntu Server
-   서버: `linux-web-01`
-   주요 확인 서비스: SSH
-   SSH 기본 포트: TCP 22
-   이전 모듈에서 완료한 내용:
    -   Ubuntu Server 환경 구성
    -   Linux 기본 명령어
    -   고정 IP 설정
    -   SSH Key 및 sudo 권한 설정

------------------------------------------------------------------------

## 3. 핵심 개념

### 3.1 systemctl

`systemctl`은 Linux의 systemd 기반 서비스 상태를 관리하고 확인하는
명령어다.

이번 실습에서는 다음 명령어를 사용했다.

``` bash
systemctl status ssh
```

주요 확인 내용:

-   `Loaded`: 서비스가 systemd에 등록되어 있는지 확인
-   `enabled`: 시스템 부팅 시 자동으로 시작하도록 설정되어 있는지 확인
-   `Active: active (running)`: 현재 서비스가 실행 중인지 확인
-   `Main PID`: 해당 서비스의 주요 프로세스 PID 확인

실습 결과 SSH 서비스는 다음과 같이 확인되었다.

``` text
Active: active (running)
```

따라서 `linux-web-01`의 SSH 서비스가 정상적으로 실행 중임을 확인했다.

참고로 처음 실행한:

``` bash
systemctl status nginx
```

에서는 `Unit nginx.service could not be found.`가 발생했다.

이는 Nginx 서비스가 현재 설치/등록되어 있지 않다는 의미였다. Nginx
설치는 다음 모듈인 모듈 6에서 진행하므로, 모듈 5에서는 SSH 서비스를
이용하여 `systemctl`의 동작을 실습했다.

------------------------------------------------------------------------

### 3.2 journalctl

`journalctl`은 systemd가 관리하는 서비스 및 시스템 로그를 조회하는
명령어다.

이번 실습에서는 SSH 서비스의 로그를 확인했다.

``` bash
sudo journalctl -u ssh
```

특정 시간 이후의 로그만 확인할 수도 있다.

``` bash
sudo journalctl -u ssh --since "2 minutes ago"
```

여기서:

-   `-u ssh`: SSH 서비스의 로그만 조회
-   `--since`: 지정한 시간 이후의 로그만 조회

실습 중 `--since` 옵션을 빠뜨려 `Invalid argument`가 발생한 뒤, 올바른
명령어를 다시 실행하여 로그를 확인했다.

SSH 접속을 직접 발생시키기 위해 다음 명령어도 사용했다.

``` bash
ssh localhost
exit
```

이후 로그에서 다음과 같은 기록을 확인했다.

``` text
Accepted password for kahuna
pam_unix(sshd:session): session opened
```

이를 통해 실제 SSH 접속 이벤트가 로그에 기록되는 것을 확인했다.

------------------------------------------------------------------------

### 3.3 ss

`ss`는 Linux에서 네트워크 소켓과 연결 상태를 확인하는 명령어다.

이번 실습에서는 다음 명령어를 사용했다.

``` bash
sudo ss -tulpen
```

옵션의 의미:

  옵션   의미
  ------ ------------------------------------
  `-t`   TCP 소켓 표시
  `-u`   UDP 소켓 표시
  `-l`   LISTEN 상태의 소켓 표시
  `-p`   해당 소켓을 사용하는 프로세스 표시
  `-e`   추가 소켓 정보 표시
  `-n`   주소와 포트를 숫자로 표시

SSH의 22번 포트를 확인하기 위해 다음 명령어도 사용했다.

``` bash
sudo ss -tulpen | grep ':22'
```

이를 통해 SSH 서버 프로세스인 `sshd`가 TCP 22번 포트를 사용하고 있는
것을 확인했다.

------------------------------------------------------------------------

## 4. 실습 과정

### STEP 1. Nginx 서비스 상태 확인

먼저 교재에 제시된 Nginx 서비스 상태를 확인했다.

``` bash
systemctl status nginx
```

결과:

``` text
Unit nginx.service could not be found.
```

Nginx가 아직 설치되지 않았음을 확인했다.

Nginx는 모듈 6에서 설치하므로 모듈 5에서는 SSH 서비스를 이용하여 서비스
상태 확인을 진행했다.

------------------------------------------------------------------------

### STEP 2. SSH 서비스 상태 확인

``` bash
systemctl status ssh
```

결과에서:

``` text
Active: active (running)
```

을 확인했다.

따라서 SSH 서비스가 정상적으로 실행 중임을 확인했다.

또한 `Loaded` 항목에서 서비스가 로드되어 있고 `enabled` 상태인 것을
확인했다.

------------------------------------------------------------------------

### STEP 3. SSH 로그 확인

전체 SSH 로그를 확인했다.

``` bash
sudo journalctl -u ssh
```

특정 시간 이후의 로그를 확인하는 방법도 실습했다.

``` bash
sudo journalctl -u ssh --since "2 minutes ago"
```

처음에는 `--since` 옵션을 잘못 입력하여 `Invalid argument`가 발생했으며,
올바른 명령어를 사용하여 로그를 정상적으로 확인했다.

------------------------------------------------------------------------

### STEP 4. SSH 접속 이벤트 발생시키기

새로운 SSH 로그를 확인하기 위해 로컬 SSH 접속을 수행했다.

``` bash
ssh localhost
```

접속 후:

``` bash
exit
```

로 세션을 종료했다.

그 후:

``` bash
sudo journalctl -u ssh --since "2 minutes ago"
```

를 실행하여 방금 발생한 접속 기록을 확인했다.

확인한 로그:

``` text
Accepted password for kahuna
pam_unix(sshd:session): session opened
```

이를 통해 SSH 접속이 서비스 로그에 기록되는 것을 확인했다.

------------------------------------------------------------------------

### STEP 5. SSH 포트 확인

``` bash
sudo ss -tulpen
```

을 실행하여 서버의 네트워크 소켓 상태를 확인했다.

이후 SSH 포트만 확인하기 위해:

``` bash
sudo ss -tulpen | grep ':22'
```

을 실행했다.

결과에서 TCP 22번 포트와 `sshd` 프로세스를 확인했다.

------------------------------------------------------------------------

## 5. 서비스 장애 분석 기본 흐름

이번 실습에서 배운 명령어를 장애 대응 과정으로 연결하면 다음과 같다.

``` text
서비스 장애 의심
       ↓
systemctl status 서비스명
       ↓
서비스가 실행 중인가?
       ↓
ss -tulpen
       ↓
필요한 포트가 LISTEN 상태인가?
       ↓
curl 또는 실제 접속 테스트
       ↓
서비스가 실제로 응답하는가?
       ↓
journalctl
       ↓
관련 로그에서 원인을 확인
```

교재의 장애 분석 표준 절차에서는 더 넓은 범위에서 다음 순서를 제시한다.

``` text
증상
 ↓
범위
 ↓
서비스
 ↓
포트
 ↓
방화벽
 ↓
로그
 ↓
해결
```

즉, 장애가 발생했을 때 감으로 판단하지 않고 상태와 로그를 명령어로
확인하면서 원인을 좁혀가는 것이 핵심이다.

------------------------------------------------------------------------

## 6. curl에 대한 실습 범위

교재의 모듈 5에서는 다음과 같은 HTTP 응답 확인도 제시되어 있다.

``` bash
curl http://192.168.56.10
```

하지만 현재 실습 시점에는 Nginx가 아직 설치되지 않았기 때문에 HTTP
서비스 응답 확인은 진행하지 않았다.

Nginx 설치 및 `curl`을 이용한 HTTP 응답 확인은 모듈 6에서 진행한다.

모듈 6에서는 다음과 같은 검증을 진행한다.

``` bash
curl http://localhost
curl http://192.168.56.10
```

따라서 모듈 5에서는 SSH를 기준으로 `systemctl`, `journalctl`, `ss`의
핵심 동작을 먼저 이해하고, HTTP 서비스 검증은 Nginx 설치 이후 연결한다.

------------------------------------------------------------------------

## 7. 실습 결과

### 서비스 상태

-   SSH 서비스: `active (running)`
-   SSH 서비스가 정상적으로 실행되고 있음을 확인

### 로그

-   SSH 접속 이벤트가 `journalctl`에 기록되는 것을 확인
-   `Accepted password`
-   `session opened`

### 포트

-   TCP 22번 포트 확인
-   `sshd` 프로세스가 SSH 서비스를 담당하고 있음을 확인

### Nginx

-   모듈 5 시점에는 설치되지 않음
-   `Unit nginx.service could not be found.` 확인
-   Nginx는 모듈 6에서 설치 예정

------------------------------------------------------------------------

## 8. 배운 점

1.  `systemctl`을 이용하여 서비스의 현재 상태를 확인할 수 있다.
2.  `journalctl`을 이용하여 특정 서비스의 로그를 확인할 수 있다.
3.  `ss`를 이용하여 서버에서 사용 중인 네트워크 포트를 확인할 수 있다.
4.  서비스가 실행 중이라는 사실과 실제 포트가 열려 있다는 사실을 각각
    확인해야 한다.
5.  서비스 장애가 발생했을 때 서비스 상태 → 포트 → 실제 응답 → 로그
    순서로 원인을 좁혀갈 수 있다.
6.  장애 대응에서는 단순히 서비스를 재시작하기보다 상태와 로그를 먼저
    확인하는 것이 중요하다.

------------------------------------------------------------------------

## 9. 면접용 요약

Linux 서버의 서비스 상태를 `systemctl`로 확인하고, `journalctl`을 통해
SSH 접속 로그를 분석했습니다. 또한 `ss`를 이용해 SSH의 TCP 22번 포트와
`sshd` 프로세스를 확인했습니다. 이를 통해 서비스 상태, 로그, 포트 정보를
함께 확인하면서 장애 원인을 단계적으로 좁혀가는 기본적인 서버 점검
방법을 실습했습니다.
